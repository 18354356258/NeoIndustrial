## 🎨 一个美术生，为什么要写工业软件？

2026 年春天，我坐在画板前画数字孪生系统的 UI 原型。

我不是计算机科班出身。我是个**美术生**——色彩、光影、构图才是我的语言。但数字孪生的世界里，你光画得好看没用——没有真实数据灌进去，再华丽的 3D 模型也只是个精致的空壳。

我需要能连上工厂里每一台设备的东西。PLC、CNC、传感器、仪表、电力柜、楼宇控制器……它们说着完全不同的语言：Modbus、S7、FOCAS、BACnet、IEC 61850……市面上的方案要么贵到离谱（一套 Kepware 够买一台机床），要么重到工控机根本跑不动（装个 Ignition 比造产线还慢），要么老旧到连 AI 的影子都看不见。

**没找到能用的。于是我放下了画笔，打开了 Visual Studio。**

不到三个月，一个人——一个美术生——从零写出了 40 个工业协议驱动、4 种数据库并行写入、MQTT 双层毫秒推送、50 个 MCP AI 原子工具、REST API、Dashboard 监控大屏。不是为了证明什么，只是真的需要一副能连接一切工业设备的神经末梢，让数字孪生活起来。

**这不是又一个"工业软件"。这是一个美术生为数字孪生世界打造的数据基座。**

现在，我把社区版完整开源——Apache 2.0，永久的、真正免费的。因为我知道：在中国做开源的工业软件有多不容易。一个人走在深夜的车间里，只有 PLC 的指示灯在闪的时候，你需要的不是更多的门槛和收费，而是一个能用的、真诚的、不设防的工具。

希望你喜欢。希望它有用。

## 🚀 5 分钟上手

### 环境要求
- Windows 7 SP1+ / Windows Server 2008 R2+
- .NET Framework 4.8（[微软官方下载](https://dotnet.microsoft.com/download/dotnet-framework/net48)）
- 4 GB+ RAM

### 安装

```bash
# 1. 克隆仓库
git clone https://gitee.com/jede_master/IndustrialDataCollector.git

# 2. 用 Visual Studio 2019+ 打开 .sln 编译
# 或者直接下载 Release 压缩包解压运行
```

### 第一个采集任务（模拟器模式，无需硬件）

1. 启动 `IndustrialDataCollector.exe`
2. 左侧设备树右键 → **添加设备** → 驱动选 `Simulator`
3. 点击 **CSV 导入** → 用模拟器默认变量 → 保存
4. 点击 **▶ 开始采集**
5. 看到数据滚动起来了

### 连接真实设备

| 设备类型 | 配置要点 |
|----------|---------|
| Modbus TCP PLC | IP + 端口 502 + 寄存器地址 + 数据类型 |
| Siemens S7-1200 | IP + Rack=0 Slot=1 + DB 地址（如 DB1.0.0） |
| Fanuc CNC | IP + 端口 8193 + 宏变量号 |
| MQTT Broker | Broker 地址 + 端口 + 主题前缀 |

## 📖 使用手册

### 设备管理（四级组织架构）

平台采用 **公司 → 车间 → 工序 → 设备** 四级树结构组织设备：

- **右键树节点** → 添加/重命名/删除文件夹或设备
- **拖拽** → 把设备移到其他工序/车间，文件夹批量迁移
- **搜索框** → 按设备名或 IP 实时过滤
- **右键「移动到…」** → 弹出路径选择对话框精准迁移

### 变量点配置

每个设备下挂载变量点（Data Points），定义采集什么、怎么处理：

| 字段 | 说明 |
|------|------|
| 变量名 | 中/英文标签（如 `温度传感器`） |
| 地址 | 协议相关地址（如 Modbus `40001`, S7 `DB1.0.0`） |
| 数据类型 | int16 / uint16 / int32 / float32 / double / string... |
| 字节序 | ABCD（大端）/ DCBA（小端）/ BADC / CDAB |
| 线性缩放 | `y = kx + b`，原始值 ×k +b = 工程值 |
| 修约 | 保留 N 位小数 |
| 报警阈值 | HH / H / L / LL 四级设定 |
| 单位 | 工程单位（℃, MPa, rpm, mm…） |

### MQTT 数据格式

每轮采集周期发一个 JSON 包到 `{TopicPrefix}/{DeviceName}`：

```json
{
  "timestamp": "2026-07-16T14:30:00.123",
  "driver": "Simulator",
  "device": "28号挤压机",
  "values": [
    {"id": "temperature", "dt": "float32", "v": 245.6, "u": "℃"},
    {"id": "pressure", "dt": "float32", "v": 32.1, "u": "MPa"}
  ]
}
```

同时每个变量有独立子话题 `{TopicPrefix}/{DeviceName}/temperature` 推送单值。

### 数据库配置

| 数据库 | 连接串示例 | 自动建表 |
|--------|-----------|:---:|
| SQLite | 默认 `Data/industrial.db` | ✅ |
| MySQL | `Server=192.168.1.100;Database=idc;User=root;Password=xxx;` | ✅ |
| SQL Server | `Server=.;Database=idc;Integrated Security=True;` | ✅ |
| PostgreSQL | `Host=192.168.1.100;Database=idc;Username=postgres;Password=xxx;` | ✅ |

4 库的表结构统一：`industrial_data(id, db_type, device, variable, data_type, value, unit, timestamp)`

### MCP AI 集成

平台内置 MCP Server，提供 50 个 AI 可调用工具。任何支持 MCP 的 AI 客户端（Claude Desktop 等）连接后即可用自然语言操控设备：

```
用户：帮我添加一台三菱 FX5U PLC，IP 192.168.1.50，采集 D100 温度、D101 压力
AI：  调用 add_device → add_variables → reload_config → 设备上线
```

工具覆盖：设备 CRUD · 变量管理 · 采集启停 · 实时查询 · 数据库查询 · 数据源管理

### CSV 批量导入模板

CSV 格式（UTF-8，Excel 可直接编辑）：

| 变量名 | 地址 | 数据类型 | 单位 | 修约 | 缩放K | 缩放B | HH | H | L | LL |
|--------|------|----------|------|------|-------|-------|----|---|---|----|
| 主机电流 | 40001 | float32 | A | 2 | 0.1 | 0 | 500 | 450 | 50 | 10 |
| 温度传感器 | 40003 | int16 | ℃ | 1 | 1 | 0 | 300 | 250 | -10 | -20 |

桌面已备模板文件：`变量点模板_ModbusTCP.csv`

### 日志与排错

- 日志目录：`Logs/log_YYYYMMDD.txt`
- 默认 **Info 级别**（启动/停止/错误/API 请求），不刷屏
- 排查采集细节时在 `Logger.cs` 中设 `LogLevel.Debug` 恢复全量
- 30 天前日志自动清理

### 🧬 语义层 · 数字孪生引擎

> 把"40001 = 245.6"变成"3号挤压车间▶1号线▶主机▶缸体温度偏高，建议检查冷却泵 #3"

- **自动建模** — 设备树 + 数据源树双路镜像，拖拽重组即变更数字孪生拓扑
- **标签体系** — 跨设备/跨协议统一变量命名空间，一套 TAG 走遍全厂
- **关系图谱** — 设备→变量→数据源三体联动，AI 可追溯任意数据的"来源设备→采集驱动→数据库表→MQTT 话题"
- **状态跟踪** — 在线/离线/停用/已删除四态标记，AI 知道什么活着、什么死了、什么时候死的
- **变量事件** — 速率、累计、持续时长等派生指标自动计算

### ⚡ Fabric 时序分析引擎

> 8 算子热插拔，比 SQL 快 10 倍，比写 Python 脚本省 100 倍时间

| 算子 | 功能 | 工业场景 |
|------|------|---------|
| **Aggregate** | 窗口聚合（avg/max/min/sum/count/stddev） | 小时均温、日峰值功率 |
| **Correlation** | 多变量皮尔逊相关系数 | 振动与温度的关联诊断 |
| **Anomaly** | 3-sigma/IQR 离群检测 | 突跳报警、传感器漂移 |
| **Digital Twin** | 理论值 vs 实测值偏差 | 能耗对标、效率衰减 |
| **Rate** | 变化率 d/dt | 温升速率、压力变化率 |
| **Accumulate** | 累积量（积分） | 总产量、总能耗、总运行时间 |
| **Threshold** | 动态上下限判定 | 自适应工艺窗口报警 |
| **Prediction** | 线性回归趋势预测 | 预测性维护、备件预警 |

分析结果随原始数据一起落入数据库，可被 MCP AI 工具实时查询。

一个人的战斗。从画 UI 原型到写低层协议栈，从前端 Dashboard 到后端时序引擎，从设计数据库 schema 到对接 40 种工业协议——全部一个人。

为什么要开源？因为我知道在中国，一个工程师想在自己的工控机上免费装一套能用的数据采集软件有多难。要么被代理商的天价授权吓回去，要么硬着头皮用盗版，要么花两个月折腾一套拼凑的开源方案最后还是连不上设备。

**不该是这样的。** 工业数据采集是数字孪生和智能制造最基础的地基——地基不应该收费，不应该加密，不应该藏着掖着。所以我把它拿出来，干干净净地开源。你不用花一分钱，不用联系我申请 License，不用看任何人的脸色——下载、编译、连接你的设备，就这么简单。

这就是 Neo 工业数采平台。**数字孪生的数据基座。**

## 🧠 为什么它牛逼

别家卖的是"协议转换器"。我们做的是**工业数据操作系统**——这几个字的差距，用一句话就能讲清楚：

> 别人让你连上设备。我们让 AI 替你管理整座工厂。

### 超前在哪

| 维度 | 行业现状（2026） | Neo 工业数采平台 |
|------|-----------------|-----------------|
| **AI 集成** | 还在讨论"AI+工业" | **50 个 MCP 原子工具，AI 原生操控**——Claude 直接帮你加设备、改配置、查数据、诊断故障 |
| **协议覆盖** | 单品类（PLC only / CNC only） | **40 种协议全品类**——PLC + CNC + 电力 + 楼宇 + 半导体 + 仪表，一套搞定 |
| **数字孪生** | 需要额外买平台 + 手动建模 | **语义层自动建模**——设备树拖拽即孪生，标签体系 AI 可推理 |
| **时序分析** | 写 Python 脚本 / SQL | **Fabric 8 算子热插拔**——异常检测、关联分析、趋势预测，配置即生效 |
| **数据出口** | 绑死自家平台 | **全部开放**——MQTT + REST API + MCP，数据想去哪去哪 |
| **部署门槛** | 服务器/集群/K8s | **单 exe 解压即用**——一台工控机跑 100 台设备，不需要运维 |

### 一己之力 vs 行业巨头

这套系统是一个人的作品。对比一下行业里的同类方案：

- **Kepware**（PTC 旗下，年费 $5000+）——驱动数量相当，但无数据库写入、无 MQTT 双层话题、无 AI 集成、无 Dashboard
- **Ignition**（Inductive Automation，$20,000+ 起步）——功能强但重如大象，需要 Java + 数据库 + Web 服务器，不是给工控机用的
- **组态王 / 力控 / 紫金桥**——学习曲线陡峭，协议库老旧，无 MCP/AI，基本停留在 2010 年
- **Node-RED / ThingsBoard**——拼凑感强，工业协议支持靠社区插件自生自灭，断网重连逻辑几乎没有

**Neo 不做任何人的竞品。它做的是数字孪生最缺的那块拼图——工业设备的数据基座。**

## 🤝 贡献

一个人可以走得很快，但一群人才能走得很远。

这个项目是一个美术生用不到三个月时间写出来的——它一定不完美，一定有 Bug，一定有你没见过但我连听都没听过的工业设备协议。**这没关系。** 开源的意义从来不在于"交出一个完美的成品"，而在于"把一个有用的东西放在这里，让需要它的人能用它、改进它、一起把它变得更好"。

如果你在厂里用它连上了 PLC 解决了实际问题——**来留个言告诉我**。那比一万个 Star 都让我开心。

如果你发现某个协议有 Bug 或者缺了你要的功能——**提 Issue、提交 PR**，哪怕只是一个错别字的修正。开源社区不是因为一个人多厉害，而是因为每个人都愿意把自己修好的那个小问题分享出来。

如果你有我没覆盖的工业设备协议——**来聊聊**。中国的工厂里藏着全世界最复杂的工业设备生态，我一个人一辈子也看不完。你贡献一个驱动，可能帮到几百个同样在用这设备的兄弟。

**互相支持，真诚相待。** 做开源不容易——深夜写代码的时候只有屏幕亮着，遇到没人踩过的坑只能自己扛，有人用你的项目但连个 Star 都不点的时候也会觉得累。但我相信：真诚的东西，迟早会遇到真诚的人。

所以，不管你来自哪个城市、哪家工厂、哪所学校——**这里是你的项目，和我们所有人的。**
