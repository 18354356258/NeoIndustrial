## 一、快速入门

### 1.1 系统要求

| 项目 | 最低要求 | 推荐配置 |
|------|----------|----------|
| 操作系统 | Windows 7 SP1 / Windows Server 2008 R2 | Windows 10 / Windows Server 2019+ |
| .NET 运行时 | .NET Framework 4.8 | .NET Framework 4.8 |
| 内存 | 4 GB | 8 GB+ |
| 硬盘 | 500 MB（不含数据存储） | SSD 1 GB+ |
| 数据库 | 内置 SQLite（零配置） | MySQL / SQL Server / PostgreSQL |

### 1.2 安装步骤

1. **获取安装包**——将程序文件夹拷贝到目标计算机，确保包含 `IndustrialDataCollection.exe` 主程序
2. **安装 .NET Framework 4.8**——如系统未安装，从微软官方网站下载并安装
3. **运行程序**——双击 `IndustrialDataCollection.exe` 启动平台
4. **首次启动**——将自动创建本地数据库和应用数据目录，无需额外配置即可使用

### 1.3 程序目录结构

| 目录/文件 | 说明 |
|-----------|------|
| `IndustrialDataCollection.exe` | 主程序 |
| `Logs/` | 运行日志（自动清理 30 天前日志） |
| `Data/` | 本地 SQLite 数据文件 |
| `Resources/Lang_zh.json` | 中文语言包 |
| `Resources/Lang_en.json` | 英文语言包 |

## 二、AI 语音管理设备

### 2.1 概述

本平台通过 MCP（Model Context Protocol）开放标准接口，支持 AI 智能助手以自然语言对话方式管理工业数据采集全流程。平台提供 **50 个 MCP 工具**，覆盖设备 CRUD、变量管理、采集控制、语义建模、数据分析等全部功能。

> **v2.6.1 新增** 分组文件夹可拖拽迁移、语义管理跨页自动联动、TDengine 多变量完整落盘。**v2.6.0 恢复** `start_device` / `stop_device` 工具。`introduce_platform(tdengine)` 可查询 TDengine 踩坑指南。`remove_device` 和 `semantic_delete_variable_relation` 需通过 UI 手动操作，确保关键操作经过安全闸门确认。

### 2.2 如何启用 MCP 服务

1. 在主界面菜单栏依次点击：**工具 → MCP 服务配置**
2. 在 McpConfigForm 中设置监听端口（默认 5100）
3. 配置 Token 认证（可选，推荐启用）
4. 点击启用服务
5. 端口被占用时自动递增尝试（最多 10 次），实际生效端口显示在日志中

> **提示：** 首次使用需以管理员身份运行，或执行 `netsh http add urlacl` 授权端口监听。

### 2.3 连接 AI 助手

1. 在 AI 助手中配置 MCP 客户端连接参数：
   - **服务地址：** `http://[本机IP]:[MCP端口]/mcp?token=[您的Token]`
   - **传输方式：** Streamable HTTP
2. 连接成功后，AI 助手将自动获取 50 个 MCP 工具列表
3. 即可开始用自然语言对话管理设备

### 2.4 用自然语言创建采集设备

连接到 AI 助手后，直接说出您的需求：

> **用户：** "帮我加一台西门子S7-1200 PLC，IP 是 192.168.1.100"

AI 将自动调用 `add_device` 工具，选择合适的协议、配置连接参数并创建设备。创建完成后设备树将自动刷新。

> **用户：** "添加一个 Modbus TCP 设备，名字叫空压机控制器，IP 192.168.1.50，端口 502"

AI 会解析您的自然语言，提取关键参数并完成设备创建。

### 2.5 用自然语言配置变量和报警

> **用户：** "在空压机控制器上监控出口温度，地址 40001，浮点数，单位摄氏度"

AI 将自动调用 `add_variables` 工具。报警配置同样简单：

> **用户：** "给出口温度加个报警，高于 80 度就告警，高于 90 度严重报警，低于 10 度也告警"

AI 会设置 HH=90℃、H=80℃、L=10℃ 四级报警阈值。

### 2.6 用 AI 生成生产日报

> **用户：** "给挤压机生成今天的生产日报"

AI 调用 `fabric_execute(daily_report)`，返回产量统计、异常汇总、趋势概要。Fabric 引擎如今支持 8 种分析算子，还可进行异常检测、相关性分析、根因定位和趋势预测。

### 2.7 示例对话：从创建到日报的完整流程

```
用户：  我需要监控工厂空压机的运行状态

AI：  好的！请告诉我设备信息和需要监控的参数。

用户：  西门子S7-1200，IP 192.168.1.50。监控出口温度、压力和运行状态

AI：  ✅ 已创建设备「空压机-S7-1200」（IP: 192.168.1.50，协议: S7）
      接下来配置三个变量，请提供寄存器地址。

用户：  温度 DB1.DBD0（浮点），压力 DB1.DBD4（浮点），状态 M0.0（布尔）

AI：  ✅ 已添加 3 个变量（℃ / MPa / 布尔）
      需要设置报警吗？

用户：  温度超过 85 度就报警，压力低于 0.3 兆帕也报警

AI：  ✅ 已配置报警规则。要现在开始采集吗？

用户：  开始采集，然后等半小时给我一份运行报告

AI：  🟢 采集已启动！
      （30 分钟后）
      📊 生产日报已生成：
      • 出口温度：平均 72.3℃（最高 81.2℃，最低 65.4℃）
      • 出口压力：平均 0.52 MPa（最高 0.61 MPa，最低 0.44 MPa）
      • 运行状态：持续运行 ✅
      • 报警事件：0 次
```

## 三、登录与激活

### 3.1 用户登录

启动程序后进入登录界面：

1. 输入**用户名**和**密码**（默认管理员账号由系统初始部署时设定）
2. 密码采用 SHA256 + SALT 加密传输，确保安全
3. 点击「登录」进入主界面

### 3.2 软件激活

首次使用需完成许可证激活：

1. 在激活界面输入从供应商获取的**许可证密钥**
2. 系统自动读取本机 **MAC 地址**进行硬件绑定（自动过滤虚拟网卡/VMware/Hyper-V/Docker）
3. 可选择**在线激活**（联网）或**离线激活**（导出申请文件→获取授权文件→导入）
4. 激活成功后，许可证信息将在 LicenseService 中存储，每次启动自动校验

## 四、数据库配置

### 4.1 配置入口

主界面菜单栏依次点击：**设置 → 数据库配置**。

### 4.2 支持的数据库类型

| 数据库 | 连接要点 | 适用场景 |
|--------|----------|----------|
| SQLite（默认） | 无需配置，程序启动后自动创建 data.db | 单机部署 |
| MySQL | 服务器地址、端口(3306)、用户名、密码、数据库名 | 中小规模 |
| SQL Server | 服务器实例名、认证方式、数据库名 | Windows 企业生态 |
| PostgreSQL | 主机、端口(5433)、用户名、密码、数据库名 | 高并发场景 |

### 4.3 v2.2 独立启用开关

每种数据库类型的启用状态独立管理，互不影响。您可以：
- 仅启用 SQLite 和 MySQL，关闭 SQL Server 和 PostgreSQL
- 同时启用全部四种数据库并行写入
- 随时切换组合，配置即时生效

### 4.4 配置步骤

1. 在数据库类型下拉框中选择目标数据库
2. 填写对应的连接参数
3. 勾选该数据库的「**启用**」开关
4. 在设备选择列表中，勾选需要写入数据的设备（留空 = 全部设备）
5. 点击「**测试连接**」验证连通性（连接超时 5 秒）
6. 测试通过后点击「**保存**」，系统将自动创建 `industrial_data` 表

> **注意：** value 列已扩容至 2000 字符，支持长 JSON 字符串。variable 列存储设备ID（GUID），tag 列存储变量ID（GUID），tag_zh 列存储中文标签路径（TagCn），详见 Q10。

### 4.5 双路独立离线缓存

MQTT 和数据库各自维护独立离线缓存：
- **offline_mqtt_cache** 表——缓存未成功发布的 MQTT 消息
- **offline_db_cache** 表——缓存未成功写入的数据库记录
- 单路故障（如数据库断连）不影响另一路（MQTT 正常发布）
- 两路恢复后各自独立补发，互不阻塞

### 5.3 添加设备流程

1. **点击「新增」**——打开新建设备对话框
2. **选择驱动协议**——从 10 种生产就绪驱动中选择
3. **配置连接参数**：

   | 参数 | 说明 |
   |------|------|
   | 设备名称 | 自定义易识别的设备名称 |
   | 协议类型 | 确认所选协议 |
   | IP 地址 / 串口号 | 设备的网络地址或 COM 端口 |
   | 端口号 | 通信端口（如 Modbus TCP 默认 502） |
   | 站号 / 单元ID | 从站地址 |
   | 超时时间 | 通信超时（毫秒） |
   | 重试次数 | 通信失败重试次数 |
   | MQTT 发布模式 | Original（仅批量）或 Resolved（批量+子话题） |

4. **编辑通道参数**（可选）——微调通道级高级参数
5. **点击「保存」**——设备将出现在数据源列表中
6. 设备状态灯将显示连接测试结果：🟢在线 / 🔴离线 / 🟡故障

### 5.4 右键操作

| 操作 | 说明 |
|------|------|
| 设备树空白区域右键 → 刷新列表 | 刷新整个设备树 |
| 分组上右键 → 刷新列表 | 仅刷新该分组下的设备 |
| 设备上右键 → 刷新列表 | 刷新单台设备的状态和连接信息 |

> **提示：** 当通过 AI 助手（MCP）添加/修改设备后，设备列表将自动刷新，无需手动操作。

### 5.5 选择性表结构分析（v2.5.0 新增）

连接大型数据库（如 TDengine 有上千张表）时，一次性获取所有表的列信息和行数可能导致界面卡死。平台提供**选择性分析**机制解决此问题：

1. 在数据源管理器中完成连接测试后，系统仅获取**表名列表**（不加载列结构和行数）
2. 表名前带有**勾选框**，选择需要分析的表
3. 使用「**全选**」/「**取消全选**」按钮进行批量勾选操作
4. 点击「**分析选中表**」按钮，系统仅对勾选的表执行列信息和行数统计
5. 分析结果支持复制导出

> **建议：** 数据库表数量超过 50 张时，推荐使用选择性分析，仅关注当前需要的表。

### 5.6 TDengine 时序数据库连接（v2.5.0 新增）

平台支持通过 REST API 连接 **TDengine 时序数据库**，用于工业时序数据的高性能存储与查询。

**配置步骤：**

1. 在数据库类型下拉框中选择「**TDengine**」
2. 填写连接参数：

   | 参数 | 说明 | 示例 |
   |------|------|------|
   | 服务器地址 | TDengine 服务 IP 或域名 | `192.168.1.200` |
   | 端口 | REST API 端口 | `6041`（默认） |
   | 数据库名 | 目标数据库名称 | `industrial_ts` |
   | 用户名 | TDengine 用户 | `root` |
   | 密码 | TDengine 密码 | `taosdata`（默认） |

3. 点击「**测试连接**」验证连通性
4. 勾选「**启用**」开关并保存配置
5. 系统自动创建超级表（STable），按设备分表存储时序数据

> **提示：** TDengine 对时序数据的写入和聚合查询性能远超传统关系型数据库，适合日均千万级数据点的工业场景。

## 六、配置变量点

### 6.1 打开设备配置

在数据源列表中双击设备，打开 **DeviceConfigForm**。

### 6.2 添加变量流程

1. 点击「**添加变量**」按钮
2. 填写变量信息：

   | 字段 | 说明 |
   |------|------|
   | 变量名称 | 中文标识（如"料筒温度"） |
   | 地址/寄存器 | 协议地址映射（如 Modbus 的 40001） |
   | 数据类型 | Int16 / Int32 / Float / Double / Bool / String |
   | 采集周期 | 数据采集间隔（毫秒） |
   | 读写权限 | 只读 / 只写 / 读写 |
   | 单位 | 工程单位（如 ℃、MPa、rpm） |

3. 填写变量名后，**中文标签路径将自动生成**——格式为"分组路径/设备名/变量名"
4. 点击「应用」

### 6.3 「应用」按钮即时生效（v2.2 更新）

变量编辑页面的"保存配置"按钮已更名为**「应用」（Apply）**：
- 点击「应用」后，配置直接写回设备模型并落盘（devices.json）
- 采集中的设备参数变更在**下一轮采集周期**自动生效，无需停止采集
- 无需返回父窗体再点击保存——一个按钮完成全部操作

### 6.4 中文标签自动生成

标签体系为纯中文：
- **设备层**：新建设备时自动计算 TagPathCn（如 `一车间/挤压机/28号挤压机`）
- **变量层**：新建变量时自动拼接中文标签（如 `一车间/挤压机/28号挤压机/料筒温度`）
- 变量列表仅显示中文标签列，无需关心英文标签

### 6.5 边缘计算配置（9 种清洗策略）

通过 **PointEditForm_Edge** 对变量启用边缘计算。平台提供 9 种清洗策略，按管线顺序执行：

**值修正类（自动修改值）：**

| 策略 | 说明 |
|------|------|
| **空值过滤** | NaN / Inf / 负数检测，可替换为上次有效值或指定值 |
| **死区抑制** | 小幅波动静默，仅当变化量超过阈值才记录 |
| **尖峰抑制** | 单点跳变 MAD 法检测，异常值用中值替换 |
| **变化率限制** | 相邻两次采集的最大变化量钳制 |
| **限幅** | 设定最大值 / 最小值，超出范围自动截断 |
| **异常值剔除** | 3σ 统计法剔除偏离均值过大的异常点 |

**质量检测类（仅记录日志，不修改值）：**

| 策略 | 说明 |
|------|------|
| **冻结检测** | 连续 N 次采集值不变时告警（传感器可能故障） |
| **IQR 四分位距** | 四分位距异常标记 |
| **量程合理性** | 超过传感器物理量程时标记 |

**管线执行顺序：** 空值过滤 → 死区抑制 → 尖峰抑制 → 变化率限制 → 限幅 → 异常值剔除 → 冻结/IQR/量程（日志）

其他边缘计算功能：
- **修约**——设置小数位数，自动四舍五入
- **滤波**——选择一阶/二阶滤波，设置滤波系数
- **报警**——配置 HH（高高）/ H（高）/ L（低）/ LL（低低）四级报警阈值
- **计算公式**——编写表达式（如 `{Temp} * 1.8 + 32` 华氏转换）

### 6.6 CSV 批量导入

设备变量较多时，推荐使用 CSV 批量导入：

1. 在设备配置界面点击「**导出模板**」，获得带表头的 CSV 模板

3. 点击「**导入 CSV**」选择填好的文件
4. 系统自动解析并批量创建变量

## 七、MQTT 配置

### 7.1 双层话题发布（v2.2 新增）

平台支持两种 MQTT 话题发布模式，在设备配置页面的 `MqttPublishMode` 参数中设置：

| 模式 | 话题格式 | 说明 |
|------|----------|------|
| **Original（仅批量）** | `{TopicPrefix}/{DeviceName}` | 每个采集周期发布一条完整设备数据包（JSON 数组） |
| **Resolved（批量+子话题）** | `{TopicPrefix}/{DeviceName}` **+** `{TopicPrefix}/{DeviceName}/{变量名}` | 同时发布批量数据包和逐变量子话题 |

**Resolved 模式消息示例（批量话题）：**

```json
{
  "timestamp": 1783176200000,
  "driver": "Simulator",
  "device": "28号挤压机",
  "values": [
    {
      "id": "28号挤压机|料筒温度",
      "dt": "float",
      "v": "72.3",
      "u": "℃",
      "variable_id": "a1b2c3d4-...",
      "tag_cn": "一车间/挤压机/28号挤压机/料筒温度"
    }
  ]
}
```

**Resolved 模式子话题示例（逐变量）：**

```
Topic: factory/workshop1/28号挤压机/料筒温度
Payload: {"timestamp":1783176200000,"variable":"料筒温度","value":72.3,"unit":"℃"}
```

### 7.2 MQTT Subscribe 订阅端 TopicFilter

对于 MQTT Subscribe 类型设备，TopicFilter 支持两种填写方式：

| TopicFilter | 说明 | 适用场景 |
|-------------|------|----------|
| `#` | 订阅该设备所有变量（批量 JSON 消息） | 一次性接收设备全部数据 |
| `/变量名` | 精确订阅单个变量（子话题消息） | 按需接收特定变量，减少带宽 |

**JSON 格式自动识别：**
- **嵌套批量格式**（含 `values` 数组）——系统自动解析为多条变量数据
- **扁平单变量格式**（含 `variable` + `value` 字段）——系统自动解析为单条变量数据
- 无需手动切换格式，系统自动适配

### 7.3 MQTT Subscribe 设备 JSON 显示

选中 MQTT Subscribe 设备后，在采集信息页面直接显示**暗色格式化 JSON**（不再使用普通网格展示），便于直观查看订阅到的原始数据报文。

### 7.4 全局 MQTT 配置

主界面菜单栏依次点击：**设置 → MQTT 配置**：

1. 填写 Broker 连接信息：
   - **Broker 地址**（如 `broker.emqx.io`）
   - **端口**（默认 1883，TLS 通常为 8883）
   - **客户端 ID**（唯一标识，留空自动生成）
   - **用户名 / 密码**（如果 Broker 需要认证）
2. 配置发布 Topic 前缀（如 `factory/workshop1/`）
3. 点击「**测试连接**」验证 MQTT Broker 连通性
4. 点击「**保存**」

> **双路离线保护：** MQTT 和数据库各自独立缓存（offline_mqtt_cache + offline_db_cache），单路故障不影响另一路。断连时数据分别写入对应缓存表，恢复后各自独立补发。

### 9.2 数据源分析工具（v2.5.0 新增）

AI 助手现在可以直接查询数据库中的数据，无需手写 SQL。通过以下 4 个专用工具，AI 可以完成从数据源发现、表结构探查到数据取样的完整分析流程：

datasource_latest_data {source_id} {table_name} [limit]

#### datasource_query_timerange — 按时间段查数据

> **💡 使用场景：** AI 接到数据分析需求时，可通过这 4 个工具自动完成数据发现→表结构探查→数据取样→分析，全程无需人工手写 SQL 或手动导出数据。

## 十二、配置损坏自动恢复（v2.2.1 新增）

### 12.1 自动恢复机制

当 `devices.json` 配置文件因意外原因损坏（如断电、磁盘满、进程崩溃）时：

1. 系统检测到 JSON 解析失败
2. 自动从 `devices.json.bak`（上次成功保存的备份）恢复
3. 损坏的文件重命名为 `devices.json.corrupted` 保留在现场，供技术人员排查
4. 日志中以 `[CRITICAL]` 标记损坏事件，以 `[RECOVERY]` 标记恢复成功

### 12.2 手动恢复

如果自动恢复失败（备份文件也不存在）：
1. 检查 `Data/` 目录下是否存在 `devices.json.corrupted` 文件
2. 尝试手动修复损坏的 JSON 并重命名为 `devices.json`
3. 重新启动程序

## 十三、配置历史版本回退（v2.3.0 新增）

### 13.1 概述

v2.3.0 新增配置文件多代历史备份功能。每次保存 `devices.json` 时，系统自动将当前版本轮转为历史备份，保留最近 **10 个历史版本**（`devices.json.bak.1` ~ `devices.json.bak.10`）。当配置误修改或需要回滚时，可随时恢复至任意历史版本。

### 13.2 查看历史版本

1. 点击主界面菜单栏 **工具 → 配置历史版本(&H)**
2. 弹出「配置历史版本管理」窗口，以列表展示各代备份：

   | 列 | 说明 |
   |----|------|
   | 版本号 | bak.1（最新） ~ bak.10（最早） |
   | 保存时间 | 该备份的创建时间戳 |
   | 文件大小 | 备份文件大小（KB） |

3. 在列表中选中目标版本，下方预览区显示该版本包含的设备数和变量数概览

### 13.3 回退到历史版本

1. 在历史版本列表中选中目标版本
2. 点击「**回退到此版本**」按钮
3. 系统弹出**二次确认对话框**，显示：
   - 目标版本号（如 bak.3）
   - 目标版本的保存时间
   - 警告："将覆盖当前配置，此操作会重新加载设备树"
4. 确认后系统执行回退：
   - 验证目标 bak 文件的 JSON 有效性
   - 将当前配置自动备份为 `devices.json.bak.0`（紧急恢复用）
   - 用历史版本内容覆盖 `devices.json`
   - 触发配置重载，设备树和采集状态自动刷新
5. 回退完成后，窗口自动关闭

### 13.4 快捷键快速回退（Ctrl+Z）

在**非文本编辑焦点**状态下（即当前焦点不在输入框内），按下 **Ctrl+Z** 快捷键可快速回退到最近一代备份（bak.1）：

1. 系统弹出二次确认对话框，显示 bak.1 的保存时间
2. 确认后，执行与"回退到此版本"相同的安全流程
3. 配置自动重载

> **注意：** 当焦点在文本编辑控件（如变量名输入框、地址输入框等）内时，Ctrl+Z 由控件自身接管为标准的文本撤销操作，不会触发配置回退。

### 13.5 注意事项

- bak.1 为最新一次保存前的版本，bak.10 为最早保留的 10 代前版本
- 每次保存 devices.json 时自动轮转，最旧的 bak.10 被丢弃
- 回退操作不可逆（除通过 bak.0 或再次回退外），请谨慎操作
- 回退前系统会验证目标备份的 JSON 有效性，**损坏的备份无法回退**
- 配置历史版本仅针对 `devices.json`，不包含 `mqtt.json` 和 `dbConfig.json`
- bak.0 仅在回退时生成（保存当前配置），正常保存不会生成 bak.0

## 十五、设备克隆（v2.4.0 新增）

设备克隆适用于同型号设备批量部署，一键复制全部配置，5 分钟上线新设备。

### 15.1 克隆操作步骤

1. 选中源设备 → 右键 → **克隆设备**
2. 输入新设备名称（默认"源设备名-副本"）
3. 选择目标分组（下拉可选）
4. 勾选克隆内容（默认全选）：驱动连接参数 / 变量列表 / 清洗策略 / Fabric 配置 / 事件规则 / 语义关系
5. 确认克隆后操作：自动标签 / 自动打开配置页面 / 自动启动采集
6. 点击 **确认克隆**

### 15.2 克隆后操作

克隆完成后系统自动打开设备配置页面，需手动修改：
- **IP 地址**（源设备 IP → 新设备 IP）
- **变量寄存器地址**（如 DB1.DBD0 → DB2.DBD0）
- 修改后点击应用，设备即可开始采集

### 15.3 克隆与模板的选择

| 场景 | 使用方式 | 原因 |
|------|----------|------|
| 同型号新设备（如 28号挤压机） | **克隆** | 变量名一致，5 分钟全配置继承 |
| 不同型号（如新注塑机） | **调用模板** | 变量名可能不同，需匹配 |
| 通用最佳实践沉淀 | **生成模板** | 跨设备类型复用 |

## 二十、常见问题

### Q1：设备显示离线但实际在线？

**排查步骤：**
1. 使用 ping / telnet 测试网络连通性
2. 检查防火墙是否放行对应端口
3. 确认协议参数（站号、波特率等）与设备一致
4. 查看 Logs/ 目录下日志了解具体错误信息

### Q2：数据写入数据库失败？

**排查步骤：**
1. 在 DatabaseConfigForm 中点击「测试连接」（连接超时 5 秒）
2. 检查数据库用户是否拥有 CREATE TABLE / INSERT 权限
3. 检查对应数据库类型的启用开关是否已打开
4. 确认 SQLite 的 FilePath 指向正确的目录
5. 数据库恢复后，OfflineCacheService 缓存数据将自动补发

### Q3：配置文件损坏如何恢复？（v2.2.1 新增）

1. `devices.json` 损坏时，系统自动从 `devices.json.bak` 恢复
2. 损坏文件保存为 `devices.json.corrupted`，可用文本编辑器打开排查原因
3. 日志中以 `[CRITICAL]` 和 `[RECOVERY]` 标记恢复过程
4. 如果备份文件也不存在（极端情况），需手动重建设备配置或从外部备份恢复

### Q4：MQTT Subscribe 设备如何订阅单个变量？（v2.2 新增）

在设备配置页的 TopicFilter 中填写 `/变量名`（以 `/` 开头），系统会精确订阅该变量的子话题消息。例如：
- TopicFilter = `#` → 接收设备所有变量（批量 JSON）
- TopicFilter = `/料筒温度` → 仅接收料筒温度变量（子话题消息）
- 系统自动识别两种 JSON 格式（嵌套批量 / 扁平单变量），无需手动切换

### Q5：驱动选择有哪些？（v2.5.0 更新）

v2.5.0 起，平台提供 **40 种工业通信驱动**，按分类呈现在驱动下拉框中（工业以太网 / CNC 数控 / 日系 PLC / 楼宇电力仪表 / 现场总线 / 物联网中继 / 其他）。其中 15 个驱动从模拟假数据升级为真实协议通信。详见第五章「5.2 设备驱动选择」的完整驱动参考表。

### Q6：如何切换语言？

在主界面菜单栏依次点击：**设置 → 语言**，选择「中文」或「English」。界面文字将立即切换。语言切换是核心功能，联动子窗体自动生效。

> **注意：** 语言切换在 MCP 配置页面等子窗口也会同步生效，无需手动刷新。

### Q7：MCP 服务连接不上？

**排查步骤：**
1. 确认 MCP 服务已启用（工具 → MCP 服务配置）
2. 检查实际生效端口（日志中查找"MCP 服务已启动"）
3. 是否以管理员身份运行（需要 `http://+:PORT/` 监听权限）
4. 端口被占用时会自动递增，查看日志确认最终端口号

### Q8：中文标签不自动生成？

**排查步骤：**
1. 确认设备已设置分组路径（非空）
2. 新建变量时，填写变量名称后标签自动生成
3. 编辑已有变量时，手动点击"自动生成标签"按钮
4. 标签路径格式：分组路径/设备名/变量名

### Q9：看板和数采页面能否同时打开？

可以。v2.2 起看板与数采页使用 Show/Activate 共存模式，您可以同时查看看板监控和操作设备配置。关闭看板会自动切回数采页面，不会退出进程。

### Q10：数据库写入的 variable / tag / tag_zh 列分别存什么？

`industrial_data` 表三列分工如下：
- **variable 列**——存储 **设备ID**（device GUID），用于程序级精确关联设备配置
- **tag 列**——存储 **变量ID**（VariableId GUID），用于程序级精确关联变量定义
- **tag_zh 列**——存储 **中文标签路径**（TagCn，如 `一车间/挤压机/28号挤压机/料筒温度`），用于人工阅读和数据直查

在数据库管理工具中直接查询时，通过 `tag_zh` 列可直观识别变量含义；通过 `variable` 和 `tag` 列的 GUID 可与 `devices.json` 中的设备和变量配置精确关联。

### Q11：如何回退配置文件到之前的版本？（v2.3.0 新增）

1. 点击菜单栏 **工具 → 配置历史版本(&H)** 打开历史版本管理窗口
2. 浏览 bak.1 ~ bak.10 共 10 个历史版本
3. 选中目标版本，点击「回退到此版本」并确认
4. 也可在非编辑状态下按 **Ctrl+Z** 快速回退到 bak.1
5. 回退前当前配置自动备份为 bak.0，紧急情况下可恢复

## 二十一、注意事项与最佳实践

1. **定期备份**——建议定期备份 `devices.json` 配置文件和 SQLite 数据文件。系统已自动维护 `devices.json.bak`（实时备份）和 `devices.json.bak.1 ~ bak.10`（10 代历史），但仍建议外部定期备份
2. **利用配置历史回退**——v2.3.0 新增 10 代历史备份，误修改配置后可随时通过工具菜单或 Ctrl+Z 回退；回退前系统会验证 JSON 有效性并保留 bak.0 紧急副本
3. **合理设置采集周期**——过短的采集周期会增加系统负载，根据实际需求设定
4. **利用边缘计算**——在数据源头做计算和过滤（9 种清洗策略），减少不必要的数据传输和存储
5. **优先使用有线网络**——工业现场建议使用有线以太网连接，确保通信稳定性
6. **许可证保管**——许可证文件与 MAC 地址绑定，更换网卡前请先联系供应商
7. **CSV 模板导入**——批量配置设备时，先导出一个变量确认模板格式，再批量填写
8. **MQTT 发布模式**——默认使用 Original（仅批量），如需逐变量子话题请切换为 Resolved
9. **「应用」键即时生效**——变量编辑页修改报警阈值/修约等参数后点击「应用」即可热生效，下一轮采集周期自动采用新参数，无需重启采集
10. **日志管理**——系统自动清理 30 天前的日志文件，采集细节日志默认关闭
11. **端口冲突**——MCP 服务端口被占用时自动递增，无需手动解决
12. **数据库独立开关**——每种数据库类型独立管理启用状态，按需组合使用
13. **看板共存**——看板与数采页可同时打开，方便监控+配置并行的场景
14. **注意高危操作**——删除设备、启停采集和删除变量关系请在 UI 中操作（v2.3.0 已从 MCP 移除这些工具），系统会弹出安全闸门二次确认
