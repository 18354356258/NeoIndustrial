## 一、认识平台

### 1.1 平台是什么

工业数采平台（企业版）是一台装在 Windows 电脑上的**工业数据采集与语义建模工作站**：向下通过 40 种工业通信驱动连接 PLC、CNC 机床、电力仪表、楼宇设备等各类设备；向上把采集数据写入 5 类数据库、通过 MQTT 发布到物联网平台；中间提供语义树建模、边缘计算清洗、事件报警、看板监控、AI 助手（MCP）、REST API 等完整能力。

核心能力一览：

| 能力 | 说明 |
|------|------|
| 设备采集 | **40 种生产就绪驱动**（全部真实协议实现），设备树分组管理、右键操作、状态灯 |
| 数据落库 | SQLite / MySQL / SQL Server / PostgreSQL / TDengine 五类数据库，**每类独立启停开关**，可并行写入 |
| MQTT 发布 | 双层话题（批量 + 逐变量子话题）、断线离线缓存、恢复自动补发 |
| 边缘计算 | 9 种清洗策略 + 修约 + 滤波 + 计算公式，在数据源头完成质量控制 |
| 语义建模 | 工厂语义树（车间/产线/设备/变量），与设备树自动同步，17 种变量关系类型 |
| 事件报警 | HH/H/L/LL 四级阈值，12 种处理方式（报警/邮件/短信/Webhook/工单/AI 分析等） |
| 看板监控 | 设备状态、实时报警、实时数据、趋势曲线、数据流速率一屏总览 |
| AI 助手 | 内置 MCP 服务（50 个工具），支持自然语言管理设备、查数、生成日报 |
| REST API | 独立 HTTP 服务 + Swagger 文档，供第三方系统取数 |
| 配置安全网 | 配置损坏自动恢复 + 10 代历史备份 + Ctrl+Z 回退 + 配置模板 + 设备克隆 |
| 网络隧道 | VPN / NAT 通道管理与 IP 映射，跨网段接入现场设备 |

### 1.2 企业版与 Web 版的关系

本产品（WinForms 桌面版）与 NeoIndustrial Web 版是**同一数据内核的两个形态**：

- 本机目录 `%LOCALAPPDATA%\IndustrialDataCollection\` 下的部分配置文件（如设备配置、数据库配置）由两款产品共用；
- 桌面版主打**现场部署、单机开箱即用**；Web 版主打多客户端浏览器访问与平台化运营；
- 两者可独立使用，也可配合使用（桌面版负责采集，Web 版负责浏览与 AI 交互）。

### 1.3 主界面导览

启动并登录后，程序首先打开**看板**（DashboardForm）作为主窗体：

## 三、五分钟上手：推荐的配置顺序

**直接回答新用户最常问的问题：先建语义树、先配 MQTT、还是先配数据库？**

> **推荐主线：先配数据库 → 再配 MQTT → 然后建分组、添加设备 → 配变量 → 启动采集验证 → 最后再建语义树和事件规则。**

**新用户推荐主线：先配数据库 → 再配 MQTT → 建分组加设备 → 配变量 → 启动采集验证 → 最后建语义树和事件规则。**

1. **配置数据库（落库目的地）**——设置 → 数据库配置。数据采下来总要有地方放，先定「写到哪」：SQLite 开箱即用，MySQL / SQL Server / PostgreSQL / TDengine 按需启用。配好即形成 industrial_data 表。
2. **配置 MQTT（上云目的地，可选）**——设置 → MQTT 配置。如果要把数据发给 EMQX / 云平台，先把 Broker 地址、话题前缀定好——后面加设备时每台设备直接引用这套全局配置，省得返工。
3. **建分组、添加设备（数据源头）**——数据源管理 → 新增设备：选驱动（40 种）、填 IP / 串口 / 站号，并挂到分组（分组路径决定中文标签，如 一车间/挤压机/28号挤压机）。
4. **配置变量（点位）**——双击设备进配置页：添加变量（地址 / 类型 / 周期 / 单位），按需配清洗策略和四级报警，点「应用」即时生效。
5. **启动采集并验证**——右键设备 → 启动采集；状态灯变绿后在看板确认实时数据、MQTT 与数据库写入状态。
6. **建语义树（组织与关系层）**——工具栏 → 语义管理。设备树会自动同步成语义层级，再补上下游关系、数据源字段绑定与事件规则。语义树不阻塞采集，放最后做不影响前五步。
7. **扩展能力（按需）**——事件通知（邮件/Webhook）、MCP 接 AI 助手、REST API 对接第三方、配置模板与设备克隆做批量部署。

**为什么是这个顺序（依赖关系）：**

| 功能 | 前置条件 | 说明 |
|------|----------|------|
| 数据落库 | 数据库配置 | 没有启用的库目标，数据只进离线缓存不落库 |
| MQTT 发布 | MQTT 配置 + 设备的发布模式 | Broker 全局一份，设备按模式引用 |
| 设备采集 | 设备 + 变量配置 | **不依赖**数据库 / MQTT / 语义树，配完设备即可采 |
| 中文标签 | 设备分组路径 | 分组变了标签路径跟着变 |
| 语义树 | 设备树（自动同步） | 数采侧层级**单向**同步到语义层，先有设备才有语义 |
| 事件规则 | 语义节点 | 事件挂在语义树的节点上 |
| 模板 / 克隆 | 至少一台配好的设备 | 从样例设备提取 |

一句话：**设备是主线，数据库和 MQTT 是目的地（先定好最省事），语义树是组织层（不着急，随时可以补）。**

## 四、数据库配置（数据写到哪）

### 4.1 配置入口

主界面菜单栏：**设置 → 数据库配置**（`DatabaseConfigForm`），配置保存在 `dbConfig.json`。

### 4.2 支持的数据库类型

| 数据库 | 默认端口 | 连接要点 | 适用场景 |
|--------|----------|----------|----------|
| SQLite | —（文件型） | 只需选择 .db 文件路径，零配置 | 单机部署 / 快速验证 |
| MySQL | 3306 | 服务器地址、端口、用户名、密码、库名 | 中小规模 |
| SQL Server | 1433 | 实例名、认证方式、库名 | Windows 企业生态 |
| PostgreSQL | 5432 | 主机、端口、用户名、密码、库名 | 高并发场景 |
| TDengine | 6041（REST） | 服务器地址、端口、库名、root 密码 | 高频时序数据（日均千万级点位） |

### 4.3 配置步骤（以 MySQL 为例）

1. 在数据库类型下拉框选择 **MySQL**（端口自动带出 3306）；
2. 填写服务器地址、端口、用户名、密码、数据库名；
3. 勾选该库的「**启用写入数据库**」开关——**五类库各自独立启停，互不影响**，可只开一个，也可全部并行写入；
4. 在设备选择列表勾选需要写入该库的设备（**留空 = 全部设备**）；
5. 可选：勾选「Fabric 历史启用」供分析引擎读取该库历史数据；
6. 点击「**测试连接**」（超时 5 秒）验证连通性；
7. 测试通过后点「**保存**」——系统自动创建 `industrial_data` 数据表。

### 4.4 数据保留天数（重要）

- 数据库配置中有「**数据保留天数**」（`RetentionDays`），**默认 7 天**；
- 清理任务**每 6 小时执行一次**，分批删除超过保留期的 `industrial_data` 历史数据；
- **设为 0（或负数）= 关闭自动清理，数据永久保留**；
- 各库实际行为：

| 数据库 | 自动清理是否生效 | 建议 |
|--------|------------------|------|
| SQLite / MySQL / SQL Server / PostgreSQL | ✅ 正常分批删除 | 按磁盘容量与合规要求设定保留天数 |
| TDengine | ❌ 当前版本清理语句在 TDengine 上不生效（时间列名不兼容，失败被静默跳过），**数据不会被删** | 保留期请直接用 TDengine 库侧 `KEEP` 参数管理（如 `ALTER DATABASE mytsdb KEEP 3650d`），平台侧建议把保留天数设为 0 |

### 4.5 数据表结构（industrial_data）

每行 = 一次采集值：

| 列 | 存什么 |
|----|--------|
| `db_type` | 目标库类型 |
| `device` | 设备名称 |
| `variable` | 变量名称 |
| `data_type` | 数据类型（float / int16 / bool…） |
| `value` | 采集值（最长 2000 字符，可存长 JSON） |
| `unit` | 工程单位 |
| `tag` | 英文标签 ID |
| `tag_zh` | **中文标签路径**（如 `一车间/挤压机/28号挤压机/料筒温度`，人工查数靠它） |
| `timestamp` | 采集时间戳 |

> TDengine 写入时保留字自动映射：`value → val`、`tag → tag_id`、`timestamp → ts`，并按设备自动创建超级表。

### 4.6 双路独立离线缓存

MQTT 和数据库**各自维护独立的离线缓存**（程序目录 `Data/offline_cache.db`）：

| 表 | 缓存内容 |
|----|----------|
| `offline_mqtt_cache` | 未成功发布的 MQTT 消息 |
| `offline_db_cache` | 未成功写入的数据库记录 |
| `device_heartbeat` | 设备心跳 |

- 单路故障不影响另一路：数据库断连时 MQTT 照常发布，反之亦然；
- 后台**每 10 秒**检查补发，链路恢复后各自独立续传，互不阻塞；
- 待发送的缓存数据**不会按天数自动删除**（断网多久都不丢数）。

## 五、MQTT 配置（数据发到哪）

### 5.1 全局 Broker 配置

主界面菜单栏：**设置 → MQTT 配置**（`MqttConfigForm`），配置保存在 `mqtt.json`：

| 参数 | 说明 | 示例 |
|------|------|------|
| Broker 地址 | MQTT 服务器 IP / 域名 | `192.168.1.200` 或 `broker.emqx.io` |
| 端口 | 明文 1883，TLS 通常 8883 | `1883` |
| Client ID | 客户端唯一标识（留空自动生成） | `collector-01` |
| 用户名 / 密码 | Broker 需要认证时填写 | — |
| 话题前缀 | 所有发布话题的根 | `factory/workshop1/` |
| QoS | 服务质量等级 | 1 |
| 自动重连 | 断线自动恢复 | 建议开启 |

填完点「**测试连接**」验证，再「**保存**」。

### 5.2 双层话题发布（每台设备可选）

在设备配置页的 `MqttPublishMode` 参数中设置：

| 模式 | 话题 | 说明 |
|------|------|------|
| **Original（仅批量）** | `{前缀}/{设备名}` | 每个采集周期发布一条完整设备数据包（JSON 数组） |
| **Resolved（批量 + 子话题）** | `{前缀}/{设备名}` + `{前缀}/{设备名}/{变量名}` | 同时发布批量包和逐变量子话题 |

批量消息示例：

```json
{
  "timestamp": 1783176200000,
  "driver": "SiemensS7",
  "device": "28号挤压机",
  "values": [
    {
      "id": "28号挤压机|料筒温度",
      "dt": "float",
      "v": "72.3",
      "u": "℃",
      "variable_id": "a1b2c3d4-...",
      "tag_cn": "一车间/挤压机/28号挤压机/料筒温度"
    }
  ]
}
```

子话题示例：话题 `factory/workshop1/28号挤压机/料筒温度`，载荷 `{"timestamp":...,"variable":"料筒温度","value":72.3,"unit":"℃"}`。

### 5.3 MQTT Subscribe 订阅型设备

如果设备/网关自己往 MQTT 发数据，用 **MQTT Subscribe** 驱动建设备，`TopicFilter` 两种写法：

| TopicFilter | 收到什么 |
|-------------|----------|
| `#` | 该设备所有变量（批量 JSON 消息） |
| `/变量名` | 精确订阅单个变量（子话题消息） |

系统自动识别「嵌套批量格式」（含 `values` 数组）与「扁平单变量格式」（含 `variable` + `value`），无需手动切换。选中订阅型设备时，采集信息页直接以**暗色格式化 JSON** 展示原始报文。

## 六、添加设备与配置变量（数据从哪来）

### 6.1 先建分组，再加设备

1. 打开**数据源管理**（`DataSourceManagerForm`）；
2. 在设备树空白区域右键 → **添加分组**，按「公司 / 车间 / 产线」建好层级（支持嵌套子分组、拖拽迁移、右键「移动到」）；
3. 点击「**新增**」打开新建设备对话框。

> 分组路径决定设备的中文标签：`一车间/挤压机/28号挤压机`。后期调整分组会改变标签路径，采集运行中会提示先停止采集。

### 6.2 驱动选择（40 种，全部生产就绪）

### 6.3 添加设备流程

1. **选择驱动协议**——下拉框按分类选择（示例：Modbus TCP 设备填 IP + 端口 502 + 站号）；
2. **配置连接参数**：

| 参数 | 说明 |
|------|------|
| 设备名称 | 现场易识别的名字 |
| 协议类型 | 所选驱动 |
| IP 地址 / 串口号 | 网络地址或 COM 口 |
| 端口 / 站号 / 单元 ID | 通信端口与从站地址 |
| 超时 / 重试 | 毫秒级超时与失败重试次数 |
| MQTT 发布模式 | Original / Resolved（见 5.2） |
| 网络通道 | 跨网段接入时选择隧道（见第九章） |

3. **编辑通道高级参数**（可选）；
4. **保存**——设备出现在设备树中，状态灯显示连接测试结果：🟢 在线 / 🔴 离线 / 🟡 故障；
5. 右键设备 → **启动采集**。

### 6.4 网络隧道（跨网段接入）

现场设备在 VPN / NAT 另一端时，不必改设备真实 IP：在数据源管理器新增/编辑页的「**网络通道**」区域：

1. 点「新建通道」打开 `TunnelEditDialog`；
2. 类型选 **VPN**（OpenVPN / L2TP / IPsec，TUN 三层或 TAP 二层）或 **NAT**（华为 AR / Moxa / 蒲公英 / 通用设备，填管理 IP、端口、账号）；
3. 维护 **IP 映射表**：`原始 IP:端口 → 映射后 IP:端口`（如 `192.168.1.50:502 → 10.8.0.5:1502`）；
4. 保存后在设备配置里选中该通道，采集即走映射地址。

### 6.5 配置变量

双击设备打开 **DeviceConfigForm**，点击「添加变量」：

| 字段 | 说明 |
|------|------|
| 变量名称 | 中文标识（如「料筒温度」） |
| 地址 / 寄存器 | 协议地址（如 Modbus 40001、S7 的 DB1.DBD0） |
| 数据类型 | Int16 / Int32 / Float / Double / Bool / String |
| 采集周期 | 毫秒（按需设置，过短会加重负载） |
| 读写权限 | 只读 / 只写 / 读写 |
| 单位 | ℃、MPa、rpm… |

填完变量名后，**中文标签路径自动生成**（`分组路径/设备名/变量名`），无需手填。

**「应用」按钮即时生效**：修改报警阈值 / 修约等参数后点「应用」，配置直接落盘（devices.json），采集中的设备**下一轮采集周期**自动采用新参数，无需停止采集。

### 6.6 边缘计算（9 种清洗策略 + 修约 + 滤波 + 公式）

通过 `PointEditForm_Edge` 启用，按管线顺序执行：

| 类别 | 策略 | 作用 |
|------|------|------|
| 值修正（改值） | 空值过滤 | NaN / Inf / 负数检测，替换为上次有效值或指定值 |
| | 死区抑制 | 小波动不记录，变化超过阈值才记 |
| | 尖峰抑制 | MAD 法检测单点跳变，中值替换 |
| | 变化率限制 | 相邻两次采集最大变化量钳制 |
| | 限幅 | 超出最大/最小值自动截断 |
| | 异常值剔除 | 3σ 统计法剔除离群点 |
| 质量检测（只记日志） | 冻结检测 | 连续 N 次值不变（传感器可能故障） |
| | IQR 四分位距 | 四分位异常标记 |
| | 量程合理性 | 超过物理量程标记 |

另支持：**修约**（小数位四舍五入）、**滤波**（一阶/二阶）、**计算公式**（如 `{Temp} * 1.8 + 32`）、**四级报警**（HH/H/L/LL）。

### 6.7 CSV 批量导入

变量多时：设备配置页点「**导出模板**」→ 在 CSV 模板中填变量（UTF-8）→「**导入 CSV**」批量创建。

## 八、语义树建模（工厂语义层）

### 8.1 入口与界面

主界面工具栏 → **语义管理**（`SemanticManagementForm`，位于数据库配置与语言切换之间）。左侧语义树，右侧三个选项卡：**节点信息 / 节点关系 / 节点事件**。

### 8.2 语义树从哪来（三向同步）

- **数采设备配置 → 语义树**：设备分组层级自动同步成语义节点（车间 / 产线 / 设备 / 变量），无需手工重建；
- **数据源 → 语义树**：数据库数据源也可纳入；
- **手动调整不被覆盖**：拖拽 / 「移动到」调整过的层级会记录 `parent_override`，后续同步不再还原；
- 反向说明：语义层的层级修改**不会**反向写回设备分组——改设备分组请回数据源管理器操作。

### 8.3 常用操作

| 操作 | 做法 |
|------|------|
| 建层级 | 右键空白 → 添加文件夹（公司/车间/产线/区域） |
| 移动节点 | 拖拽，或右键 →「移动到」选择目标父节点 |
| 大树不卡 | 节点超过 200 自动启用懒加载，搜索走内存缓存 |
| 变量关系 | 在「节点关系」Tab 建立变量与数据源表字段 / 常量 / 表达式的绑定，及上下游关系（17 种关系类型） |
| 节点事件 | 在「节点事件」Tab 配置事件规则（见第十章） |
| 同步节点状态 | 同步节点的状态由设备驱动，不可手改；手动节点可自由编辑 |

## 九、事件与报警（12 种处理方式）

### 9.1 在哪配置

事件规则挂在**语义树的节点**上：语义管理 → 选中节点 →「节点事件」Tab → 添加事件规则：选触发条件（变量超限 / 状态变化 / 设备离线）→ 选处理方式（可多选）→ 填处理参数（收件人 / Webhook URL 等）。

### 9.2 12 种处理方式

| 处理方式 | 场景 |
|----------|------|
| 仅记录 | 留痕不响应 |
| 报警 | 现场人工确认（HH/H/L/LL 四级阈值） |
| 消息通知 / 站内消息 | 提醒操作员 |
| 邮件 / 短信 | 远程通知 |

### 9.3 报警消息格式

```
[ALARM HH] [28号挤压机] 料筒温度 = 92.5 ℃
```

`[设备名]` 前缀让多设备场景一眼定位报警来源；看板报警面板 20 分钟窗口自动清除、同类合并计数。

## 十二、配置安全网（不怕改坏）

| 机制 | 说明 |
|------|------|
| 损坏自动恢复 | `devices.json` 解析失败时自动从 `.bak` 恢复；损坏文件保留为 `.corrupted` 供排查；日志标记 `[CRITICAL]` / `[RECOVERY]` |

## 十四、常见问题（FAQ）

**Q1：设备显示离线但实际在线？**
① ping / telnet 测网络连通性；② 防火墙放行对应端口（如 Modbus 502、S7 102）；③ 核对站号 / 波特率等参数与设备一致；④ 跨网段设备确认已选择网络通道（第九章）；⑤ 查 `Logs/` 日志具体报错。

**Q2：数据写不进数据库？**
① 数据库配置里点「测试连接」（5 秒超时）；② 确认该库的「启用写入数据库」开关已勾选；③ 确认数据库账号有 CREATE TABLE / INSERT 权限；④ SQLite 检查文件路径；⑤ 断连期间数据在 `offline_db_cache`，恢复后自动补发；⑥ 检查设备是否勾选进该库的写入设备列表（留空 = 全部）。

**Q3：7 天前的数据没了 / 想让数据永久保留？**
数据库配置里「数据保留天数」默认 7 天，每 6 小时清理一次。**设为 0 即永久保留**。注意：TDengine 目标当前版本自动清理不生效，数据不会被平台删除，保留期请用 TDengine 的 `KEEP` 参数管理。

**Q4：MQTT 断连会丢数据吗？**
不会。MQTT 与数据库双路独立缓存（`offline_mqtt_cache` / `offline_db_cache`），每 10 秒检查补发，恢复后自动续传，断多久都不丢。

**Q5：MQTT Subscribe 设备如何只订阅一个变量？**
TopicFilter 填 `/变量名`（以 `/` 开头）精确订阅子话题；填 `#` 收全部。系统自动识别批量 / 单变量两种 JSON 格式。

**Q6：MCP / AI 助手连接不上？**
① 确认 MCP 服务已启用；② 以日志里的「实际生效端口」为准（默认 5101，被占用自动 +1）；③ 权限不足时管理员运行或 `netsh http add urlacl`；④ Token 要与配置一致；⑤ 传输方式选 Streamable HTTP。

**Q7：中文标签没有自动生成？**
① 确认设备已挂到分组（标签 = 分组路径/设备名/变量名）；② 新建变量填完名称自动生成；③ 编辑旧变量点「自动生成标签」按钮。

**Q8：配置改坏了怎么回退？**
工具 → 配置历史版本 → 选中版本 →「回退到此版本」；或非编辑状态按 **Ctrl+Z** 快速回退上一版。损坏自动恢复机制也会兜底（`.bak` → 自动回滚）。

**Q9：看板和数采页能同时开吗？**
能，v2.2 起共存模式，一边监控一边改配置。关闭看板自动切回数采页，不退出进程。

**Q10：industrial_data 表里哪一列能看出数据是哪个变量的？**
人查数据看 `tag_zh`（中文标签路径，如 `一车间/挤压机/28号挤压机/料筒温度`）；`device` 是设备名、`variable` 是变量名；TDengine 里对应列名映射为 `tag_id / val / ts`。

**Q11：批量上 10 台同型号设备，逐台配太慢？**
配好 1 台 → 右键**克隆设备**（勾选全部内容）→ 改新设备 IP 和寄存器地址 → 应用 → 启动采集。不同型号用**配置模板**按变量匹配套用。

**Q12：数据库表很多（如 TDengine 上千张表）时数据源分析卡死？**
数据源管理器已做**选择性分析**：测试连接后只拉表名列表 → 勾选要看的表 →「分析选中表」批量获取列信息与行数，结果可复制导出。

**Q13：提示「工业数采平台已在运行中」？**
程序防双开（全局互斥锁）。如需重启，先关闭当前实例（托盘右键退出）；若上次异常退出残留锁，等几秒重试或用任务管理器结束旧进程。

**Q14：忘记 admin 密码？**
账号库在配置目录 `auth.db`。请联系技术支持（18854344113 / 751326339@qq.com）协助重置，勿直接删除 auth.db 以免丢失其他配置关联。

**Q15：MCP / REST 端口提示权限不足？**
两个服务默认监听全网卡（`http://+:端口/`）。以管理员身份运行程序，或一次性授权：`netsh http add urlacl url=http://+:5101/ user=Everyone`（REST 为 5000）。

**Q16：升级 / 换机部署要注意什么？**
备份整个配置目录（重点是 `devices.json`、`groups.json`、`mqtt.json`、`dbConfig.json`、`semantic_v2.db`、`license.dat`）；`license.dat` 与 MAC 绑定，换机前先联系技术支持重新授权。

## 十五、注意事项与最佳实践

1. **先改默认密码**（admin/admin），正式环境必做；
2. **定期外部备份**配置目录与 SQLite 数据文件（系统已有 10 代自动备份，双保险更稳）；
3. **采集周期按需设置**，过短加重设备与网络负载；
4. **优先在源头做清洗**（边缘计算 9 策略），减少无效数据传输与存储；
5. **工业现场用有线网络**，无线仅做辅助；
6. **TDengine 的保留期用库侧 KEEP 管理**，平台侧保留天数设 0（见 Q3）；
7. **变更分组层级前先停止采集**（标签路径会变，程序会提示确认）；
8. **批量部署**：克隆（同型号）+ 模板（跨型号）组合使用；
9. **高危操作走 UI**：删除设备、删除变量关系在界面操作并二次确认，不经 MCP；
10. **日志 30 天自动清理**，重要问题及时导出 `crash.log` 与当日日志。
