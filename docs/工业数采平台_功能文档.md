## 一、平台概述

工业数采平台（Neo_IndustrialDataCollector）是一套面向工业现场的综合数据采集与管理平台，支持 **40 种工业驱动协议**、**5 种数据库**、**17 个核心服务**以及 **50 个 MCP 语义 AI 工具**。平台以 .NET Framework 4.8 为运行时，采用 WinForms 桌面客户端架构，覆盖从设备接入、数据采集、边缘计算、事件处理、数据路由到云端发布的完整工业数据链路。

v2.4.0 在 v2.3.0 基础上，核心新增**配置模板引擎**和**设备克隆**两大生产力特性，大幅提升多设备批量部署效率：
- **配置模板引擎** — 支持从设备提取配置生成可复用模板（JSON），通过精确/正则/包含三种匹配模式一键应用至目标设备，含模板管理器（分类树+搜索+详情预览）
- **设备克隆** — 右键设备一键克隆，深拷贝全部配置（驱动/变量/清洗/Fabric/事件/语义关系），自动生成新GUID和中文标签，同型号设备 5 分钟上线
- **4 个新窗体：** TemplateManagerForm / TemplateApplyForm / TemplateGeneratorForm / DeviceCloneForm
- **UI 增强：** 工具菜单新增「配置管理(&M)」入口，设备右键菜单新增「克隆设备」+「配置模板」子菜单

v2.3.0 在 v2.2.1 基础上，从分析引擎增强、数据语义规范化、配置安全升级、操作体验优化四个维度进行了全面升级，核心新增：

- **Fabric 引擎算子扩展至 8 个** — 新增 `anomaly_detect`（时序异常模式识别：spike 突跳 / drift 漂移 / periodic 周期异常）、`correlation`（多变量皮尔逊相关性矩阵分析）、`root_cause`（根因定位含时滞相关性扫描 ±max_lag_seconds）、`predict`（线性回归外推预测含 95% 置信区间）
- **数据库字段语义变更（v2.2.1+）** — `industrial_data` 表 `variable` 列改为存设备ID（GUID），`tag` 列改为存变量ID（GUID），`tag_zh` 列存中文标签路径，实现数据与设备/变量的精确关联
- **配置文件多代历史备份（v2.3.0 新增）** — 10 代轮转备份（devices.json.bak.1 ~ bak.10），工具菜单「配置历史版本(&H)」弹窗浏览回退，Ctrl+Z 快捷键快速恢复，RestoreFromHistory(int) API 含 JSON 有效性验证 + 二次确认
- **报警消息增强** — 报警日志格式新增 `[设备名]` 前缀，多设备场景可一眼定位报警来源
- **MCP 工具安全精简（43 个）** — 移除 4 个高危工具（remove_device / start_device / stop_device / semantic_delete_variable_relation），设备 CRUD 保留 5 个，语义写入保留 5 个
- **语义管理入口优化** — 从工具菜单 MenuItem 改为工具栏 ToolStripButton，位于数据库配置和语言切换之间，操作更便捷
- **MEMORY.md 规则 57 条** — 从 56 条扩展到 57 条开发规范

此外，v2.2.1 奠定的基础能力包括：生产就绪驱动白名单（10 个）、JSON 深拷贝模型体系、MainForm.DeviceTree.cs 分部类、ApplicationLifecycle 统一生命周期、数据库连接超时优化（15s→5s）、损坏 JSON 自动恢复（.bak + .corrupted）、静默异常消除、Dispose 资源清理、SALT 环境变量优先、MSTest 测试项目、MQTT 双层话题发布、MQTT Subscribe 智能 JSON 解析、DB value 列扩容 NVARCHAR(2000)、OfflineCacheService 双表独立缓存、9 种数据清洗策略、语义管理单向映射重构、树拖拽 parent_override 持久化等核心增强。

### 4.1 ApplicationLifecycle 统一生命周期管理（v2.2.0 新增）

**ApplicationLifecycle** 统一管理应用启动与关闭的步骤顺序，解决启动/关闭顺序混乱和资源泄漏问题：

- **Register（注册）** — 按启动顺序注册关闭回调：REST API → MCP → OfflineCache → DB Retention → SaveRunningState（共 5 步）
- **Shutdown（逆序关闭）** — 最后注册的最先关闭，保证依赖关系正确：先 UI（定时器/看板），再数据采集，再网络服务（MQTT/REST/MCP），最后持久化（缓存/DB）
- **每步独立超时保护** — 默认每步 5 秒超时，单步失败不影响后续步骤
- **关键/非关键步骤标记** — isCritical 参数控制失败时是否继续执行

### 5.1 数据库写入启用开关（v2.2.1 新增）

DatabaseWriteService 支持 **per-type 独立隔离**：MQTT 写入开关和 DB 写入开关各自独立控制，某一路故障不会影响另一路正常写入。

### 5.2 ConfigService 配置安全（v2.2.1 新增）

- **SaveDevices 自动备份** — 每次保存 devices.json 前自动备份现有文件为 devices.json.bak
- **SafeReloadFromFile** — 防止局部保存导致文件截断，写入完成后再替换
- **LoadDevices 损坏恢复** — JSON 反序列化失败时，自动尝试从 .bak 恢复；同时保留损坏文件为 .corrupted 供人工排查，[CRITICAL] 级别日志记录全程

### 5.3 配置文件多代历史备份（v2.3.0 新增）

平台为 `devices.json` 配置文件提供 **N 代轮转历史备份** 机制，支持配置误操作回退：

**轮转策略：**
- 每次保存时自动执行轮转：`bak.9 → bak.10`、`bak.8 → bak.9`、...、`bak.1 → bak.2`、`当前 → bak.1`
- 默认保留 **10 代**历史版本（`devices.json.bak.1` ~ `devices.json.bak.10`）
- bak.1 为最新一次保存前的版本，bak.10 为最早保留的版本

**UI 入口：**
- 主菜单 工具 → 「**配置历史版本(&H)**」弹窗
- 弹窗以列表展示各代备份：版本号、保存时间戳、文件大小
- 支持选中任意历史版本进行回退操作

**快捷键回退：**
- **Ctrl+Z** 快捷键（非文本编辑焦点时）快速回退到最近一代备份（bak.1）
- 文本编辑控件获得焦点时 Ctrl+Z 由控件自身处理（标准撤销），不触发配置回退

**回退流程与安全保护：**
1. 用户选择回退版本或按下 Ctrl+Z
2. 系统弹出**二次确认对话框**，说明目标版本号、保存时间及"将覆盖当前配置"的警告
3. 确认后，`RestoreFromHistory(int generation)` 方法执行：
   - 验证目标 bak 文件的 **JSON 有效性**（解析成功才算有效）
   - 验证通过后，将**当前配置自动备份为 bak.0**（紧急恢复用）
   - 用历史版本内容覆盖 devices.json
   - 触发配置重载，设备树和采集状态自动刷新
4. JSON 损坏的 bak 文件无法回退，弹窗提示用户选择其他版本

### 5.4 数据源管理器选择性表结构分析（v2.5.0 新增）

数据源管理器（DataSourceManagerForm）的连接测试与表结构分析流程优化为按需执行模式，避免全量扫描带来的性能开销：

**工作流程：**

1. **测试连接** — 仅验证数据库可达性，成功后仅获取表名列表（不读取列信息和行数）
2. **勾选表** — 用户在表名列表中勾选需要分析的目标表（可多选）
3. **分析选中表** — 点击"分析选中表"按钮后，仅对已勾选的表执行列信息获取和行数统计
4. **同步语义层** — 仅已分析的表的字段信息会被同步到语义层，未分析的表不参与语义层同步

**设计优势：**

- **按需分析** — 大型数据库中可能存在数百张表，全量扫描每个表的列和行数将产生大量查询；勾选机制确保只分析用户关心的表
- **语义隔离** — 未分析的表不会出现在 MCP 工具的数据库直查中，避免语义层膨胀
- **二次确认** — 用户勾选操作即是对表的使用意图确认，减少误操作影响

#### 8 种分析算子

##### 1. window_aggregate — 滑动窗口聚合分析

对单变量或多变量时序数据在指定滑动窗口内执行聚合统计。

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `window_seconds` | int | 窗口大小（秒） |
| `variable_names` | string[] | 目标变量名列表 |
| `functions` | string[] | 聚合函数：avg / min / max / sum / count / stddev |

**输出：** 每个变量在每个窗口内的聚合值序列。

##### 2. trend_detect — 趋势检测（线性回归）

基于滑动窗口内数据的线性回归，检测上升或下降趋势。

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `window_seconds` | int | 窗口大小（秒） |
| `slope_threshold` | double | 斜率阈值（单位/秒），超过此值判定为趋势 |
| `r_squared_min` | double | 最小 R² 拟合度，低于此值视为无显著趋势 |

**输出：** 趋势方向（上升/下降/平稳）、斜率、R² 值。

##### 3. threshold_alarm — 统计阈值报警（μ±kσ）

基于历史数据的均值（μ）和标准差（σ）动态计算报警阈值，比固定阈值更适应工况变化。

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `window_seconds` | int | 统计窗口大小（秒） |
| `sigma_multiplier` | double | σ 倍数（典型值 3.0） |
| `time_range` | string | 时间范围（realtime / 5m / 1h / 24h / 7d） |

**输出：** 当前值、动态上限（μ+kσ）、动态下限（μ−kσ）、是否触发报警。

##### 4. daily_report — 生产日报

按设备列表和日期生成结构化生产日报，支持 HTML 输出。

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `device_names` | string[] | 设备名称列表 |
| `date` | string | 报表日期（yyyy-MM-dd） |
| `sections` | string[] | 分节内容：summary / stats / alarms |
| `output_format` | string | 输出格式（默认 HTML） |

**输出：** HTML 格式生产日报，包含产量统计、运行时长、异常汇总、趋势概要。

##### 5. anomaly_detect — 时序异常模式识别（v2.3.0 新增）

对时序数据进行多模式异常检测，自动识别三种异常类型：

| 异常类型 | 检测算法 | 说明 |
|----------|----------|------|
| **spike（突跳）** | 滑动窗口 MAD 法 | 单点值偏离窗口中位数超过阈值（默认为 5 倍 MAD），判定为瞬时尖峰 |
| **drift（漂移）** | 线性回归斜率检测 | 窗口内数据拟合斜率超过阈值且持续累加，判定为缓慢漂移 |
| **periodic（周期异常）** | 自相关函数（ACF） | 检测周期性模式的幅值或周期突变，偏离历史基线超过阈值 |

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `variable_name` | string | 目标变量名 |
| `window_seconds` | int | 分析窗口大小（秒） |
| `anomaly_types` | string[] | 检测类型：spike / drift / periodic（可多选） |
| `sensitivity` | double | 灵敏度系数（0.5~3.0，默认 1.0，越小越敏感） |

**输出：** 异常事件列表，每项包含异常类型、发生时间戳、异常值、偏离程度和严重等级。

##### 6. correlation — 多变量皮尔逊相关性矩阵分析（v2.3.0 新增）

对多个变量的时序数据两两计算皮尔逊相关系数，生成相关性矩阵。

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `variable_names` | string[] | 待分析变量列表（≥2 个） |
| `window_seconds` | int | 分析窗口大小（秒） |
| `min_correlation` | double | 最小相关系数阈值（默认 0.5，低于此值不报告） |

**输出：** 相关性矩阵表格，每对变量返回相关系数 r、p 值、显著性标记（∗ / ∗∗ / ∗∗∗）。

##### 7. root_cause — 根因定位含时滞相关性扫描（v2.3.0 新增）

当目标变量出现异常时，扫描所有候选变量的时滞相关性，定位最可能的根因变量和传导时滞。

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `target_variable` | string | 出现异常的目标变量名 |
| `candidate_variables` | string[] | 候选根因变量列表 |
| `max_lag_seconds` | int | 最大时滞扫描范围（秒），±max_lag_seconds |
| `window_seconds` | int | 分析窗口大小（秒） |

**算法：**
1. 对每个候选变量，在 `[-max_lag_seconds, +max_lag_seconds]` 范围内逐秒偏移，计算与目标变量的皮尔逊相关系数
2. 取最大相关系数对应的时滞作为该候选变量的最优时滞
3. 按最大相关系数降序排列，Top-N 候选变量作为根因排序输出

**输出：** 根因候选排序列表，每项包含候选变量名、最优时滞（正=候选领先、负=候选滞后）、最大相关系数、置信度评分。

##### 8. predict — 线性回归外推预测含 95% 置信区间（v2.3.0 新增）

基于历史时序数据进行线性回归建模，外推预测未来时刻的期望值及不确定性范围。

| 关键参数 | 类型 | 说明 |
|----------|------|------|
| `variable_name` | string | 目标变量名 |
| `history_window_seconds` | int | 历史数据窗口大小（秒） |
| `predict_steps` | int | 预测步数（每步 = 采集周期） |
| `confidence_level` | double | 置信水平（默认 0.95，即 95%） |

**算法：**
1. 对历史窗口内数据点 (tᵢ, vᵢ) 拟合线性回归 y = β₀ + β₁·t
2. 计算回归标准差 SE 和置信区间半宽 `t_{α/2,n-2} · SE · √(1/n + (t-t̄)²/Σ(tᵢ-t̄)²)`
3. 在预测步数范围内外推，返回预测值 + 95% 置信区间上下界

**输出：** 预测时间序列，每步包含预测值、置信下限、置信上限、预测趋势方向（上升/下降/平稳）。

### 7.3 可插拔数据出口（DataStreamEngine + ISink）

v2.0 重新设计了数据发布通道，采用 ISink 接口抽象 + DataStreamEngine 路由模式：

```
Driver → CycleDataBatch → [WAL 缓存] → DataStreamEngine
                                              │
                    ┌─────────────────────────┼─────────────────────────┐
                    ▼                         ▼                         ▼
               MqttSink                 DatabaseSink               自定义 Sink
          (MQTT 双层话题发布)            (SQLite/MySQL/...)         (用户扩展)
```

**ISink 接口：**

```csharp
public interface ISink
{
    string Name { get; }
    bool IsReady { get; }
    Task<bool> WriteAsync(DataBatch batch, CancellationToken cancellationToken);
}
```

**DataStreamEngine 路由流程：**
1. CycleDataBatch → DataBatch 归一化（提取 VariableId、TagId、TagCn、DeviceId）
2. 查询设备 MqttPublishMode（Original / Resolved）
3. 并发调用所有 ISink.WriteAsync()
4. 返回各出口成功/失败字典

**内置出口：**

| 出口 | 实现 |
|------|------|
| MqttSink | 通过 MqttPublishService.PublishRawAsync() 发布，**v2.2.1 支持双层话题（批量 + 逐变量）**，支持 Original/Resolved 双模式 |
| DatabaseSink | 重建 CycleDataBatch 后调用 DatabaseWriteService.WriteBatchAsync() 写入所有启用的数据库，**per-type 独立隔离** |

### 7.4 MQTT 双层话题发布（v2.2.1 新增）

v2.2.1 在原有单一批量话题基础上新增逐变量子话题发布：

| 层级 | 话题格式 | 内容 | 适用场景 |
|------|----------|------|----------|
| **批量话题** | `{TopicPrefix}/{DeviceName}` | 完整数据包：timestamp + driver + device + values 数组 | 一次性消费全设备数据 |
| **逐变量话题** | `{TopicPrefix}/{DeviceName}/{VariableName}` | 单变量数据包：timestamp + driver + device + variable + value + unit | 按变量粒度订阅、告警联动 |

**MqttPublishMode 控制：**

| 模式 | 批量话题 | 逐变量话题 | 说明 |

| 格式类型 | 识别特征 | 处理方式 |
|----------|----------|----------|
| **嵌套 JSON + values[] 数组** | 顶层包含 `values` 数组，内含 `tag_cn` 字段 | 遍历 values 数组，按 tag_cn 匹配本地变量名提取 value |
| **单变量 JSON** | 顶层包含 `variable` + `value` 字段 | 直接提取 variable 名称和 value 值 |
| **原始格式** | 以上两种都不匹配 | 保持原有解析逻辑 |

### 13.1 用户认证与安全

- **密码加密：** SHA256 + SALT 哈希存储，不可逆。**v2.2.1 SALT 优先从环境变量 IND_SALT 读取**，未设置时使用内置默认值（文档注明 SHA256 应迁移到 bcrypt/argon2）

- **REST API：** Token 认证（Bearer Token），支持过期刷新
- **MCP 服务：** Token 认证（`?token=xxx` 查询参数），端口自动抢占

### 13.3 WAL 离线缓存与断网补发（v2.2.1 双表独立）

当数据库连接或 MQTT Broker 不可用时：

- **WAL 双表独立缓存：** 采集数据分别写入 `offline_mqtt_cache` 和 `offline_db_cache` 两张独立表
- **双路并行恢复：** MQTT 和 DB 各自独立标记、恢复、清理，互不阻塞（MQTT 通即清 MQTT 表，DB 通即清 DB 表）
- **10s 定时器同时检查两路：** 单一定时器每 10 秒同时检查 MQTT 连接和 DB 连接状态，触发各自的恢复流程
- **事务保护：** StoreBatch 一次写入两行使用 SQLite 事务保证原子性
- **数据完整性：** 单路故障不影响另一路，故障恢复后自动补发丢失数据

### 13.4 设备健康状态 SSOT

DataProcessor 服务作为单一真相来源（SSOT），基于数据驱动的判定模型持续评估每台设备的健康状态（正常/告警/故障/离线），避免多点状态冲突。

## 十四、配置模板引擎（v2.4.0 新增）

配置模板引擎解决工业现场「一台设备调试两周，第二台同型号还要两周」的核心痛点。从已配置的设备提取语义关系、Fabric 参数、事件规则、清洗策略，序列化为 JSON 模板，后续通过变量名匹配一键应用到新设备。

### 14.1 模板数据模型

模板文件以 JSON 格式存储在 `templates/` 目录下，核心结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| `template_id` | string | 唯一标识（`tpl_` + 12 位 hex） |
| `template_name` | string | 模板名称 |
| `category` | string | 分类路径，支持 `/` 多级（如"挤压机/温度监控"） |
| `version` | string | 版本号（如 1.0） |
| `created_from_device` | string | 来源设备名称 |
| `variable_patterns` | array | 变量匹配规则列表（模板变量名/匹配方式/数据类型/单位） |
| `semantic_relations` | array | 语义关系模板（源变量/目标变量/关系类型） |
| `fabric_configs` | array | Fabric 算子参数模板（算子名/目标变量/参数/启用状态） |
| `event_rules` | array | 事件规则模板（规则名/触发条件/动作列表） |
| `cleaning_strategies` | array | 清洗策略模板（目标变量/策略类型/参数/启用状态） |
| `inheritance_config` | object | 继承控制（跳过缺失变量等） |

### 14.2 三种变量匹配模式

| 模式 | 逻辑 | 适用场景 |
|------|------|----------|
| **精确匹配** | 变量名完全相同 | 同型号设备变量名一致时（推荐） |
| **包含匹配** | 模板变量名包含在实际变量名中或反之 | 变量命名有统一前缀/后缀 |
| **正则匹配** | `Regex.IsMatch(实际变量名, 正则表达式)` | 变量命名遵循某种模式 |

### 14.3 模板生成流程

```
选中设备 → 右键 → 配置模板 → 新建模板
  → 填写名称/分类/描述
  → 选择包含模块（语义/Fabric/事件/清洗）
  → 选择变量匹配方式
  → 预览变量映射列表
  → 确认生成 → templates/{template_id}.json
```

### 14.4 模板应用流程

```
选中目标设备 → 右键 → 配置模板 → 调用模板
  → 浏览模板库（分类树+搜索）
  → 预览模板详情（变量/关系/Fabric/事件/清洗数量）
  → 确认应用
  → 系统逐模块匹配变量 → 仅写入匹配成功的配置
  → 生成应用报告（Logs/TemplateApply_*.log）
```

### 14.5 模板管理器（v2.5.0 重设计）

## 十五、设备克隆（v2.4.0 新增）

设备克隆解决「同型号设备批量部署」场景——一键深拷贝已有设备的全部配置，仅需修改 IP 地址和寄存器地址即可上线。

### 15.1 克隆流程

```
选中源设备 → 右键 → 克隆设备
  → 输入新设备名（默认"源设备名-副本"）
  → 选择目标分组
  → 勾选克隆内容（驱动/变量/清洗/Fabric/事件/语义关系，默认全选）
  → 选择克隆后操作（自动标签/打开配置/启动采集）
  → 预览克隆项目
  → 确认克隆
  → 系统执行：JSON 深拷贝 → 新 GUID（设备+变量） → 语义关系 ID 映射 → TagCn 重生成
  → 自动打开设备配置页面（方便修改 IP 和寄存器地址）
```

### 15.2 与模板功能的区别

| 维度 | 模板功能 | 克隆功能 |
|------|----------|----------|
| 适用场景 | 不同设备类型，继承通用配置 | 同型号设备，继承全部配置 |
| 变量映射 | 需要匹配（可能部分失败） | 变量名完全一致，无需匹配 |
| 配置范围 | 可选择继承哪些模块 | 全部继承（除名称/IP/变量地址外） |
| 源设备 | 可以删除，模板仍保留 | 源设备必须存在 |
